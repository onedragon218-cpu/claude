# 상장기업 장기 재무성과 분석 시스템 — 사용 설명서

종목코드를 넣으면 과거 10년 실적, 현재 연도, 향후 2년 컨센서스로 7개 지표(매출액, 영업이익률, EPS, BPS, ROE, 부채비율, 시가총액)를 모으고 검증해서 SQLite DB에 쌓는다. 같은 종목을 다시 조회하면 **DB에 없는 값만** 수집한다.

- 별도 설치 없음: Python 3.10 이상, 표준 라이브러리만 사용
- DB: `data/analyzer.db` · 화면: `data/output/<종목코드>.html` (윈도우 설치 시 `%LOCALAPPDATA%\CorpAnalyzer\data`)

## 1. 빠른 시작

```bash
python -m analyzer analyze 213500          # 한솔제지 분석 → data/output/213500.html
python -m analyzer analyze 213500          # 다시 실행: 외부 요청 0건, 기존 값 재사용
python -m analyzer analyze 005930 --base-year 2027   # 다른 종목, 기준 연도 변경
python -m analyzer serve                   # http://localhost:8765 에서 화면 A~F 사용
```

기타 명령

| 명령 | 하는 일 |
|---|---|
| `python -m analyzer status 213500` | 상태별 값 개수, 컨센서스 스냅숏 수, 변경 이력 수 |
| `python -m analyzer report 213500` | 수집 없이 화면만 다시 만들기 |
| `python -m analyzer import-consensus 213500 파일.csv` | 컨센서스를 CSV로 넣기(시점별 저장) |
| `python -m analyzer reverify 213500 --year 2024` | 사용자 재검증 요청: 해당 연도 값을 STALE로 바꾸고 다음 실행 때 다시 받아 비교 |
| `python -m analyzer update-all` | DB의 모든 기업 갱신(자동 실행용) |
| `python -m unittest discover -s analyzer/tests -t .` | 시험 10개 |

화면 C(통합 그래프)는 위쪽 탭으로 **표준화 비교**와 **지표별 원데이터**(실제 단위 그래프, 연도별 표)를 오갈 수 있습니다. 마지막으로 고른 탭은 브라우저에 기억됩니다.

## 2. 자동 수집(GitHub Actions)

이 개발 환경에서는 DART·FnGuide·네이버 접속이 막혀 있어서, **수집 코드는 GitHub 서버에서 자동으로 실행**되도록 `.github/workflows/collect.yml`을 넣었다.

- 매주 월·목 07:13(한국시간)에 DB의 모든 기업을 갱신하고, 바뀐 DB와 화면을 저장소에 커밋한다.
- Actions 화면의 "Run workflow"로 언제든 수동 실행할 수 있다(종목코드, 기준 연도 입력 가능).
- 처음 한 번은 아래 설정이 필요하다.

**해야 할 일(순서대로)**
1. DART 인증키 발급: https://opendart.fss.or.kr → 인증키 신청/관리 → 인증키 신청(무료, 보통 당일 발급)
2. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret
   - Name: `DART_API_KEY`
   - Secret: 발급받은 40자리 키
3. 예약 실행은 **기본 브랜치에 workflow 파일이 있어야** 동작한다. 이 브랜치를 기본 브랜치에 병합하거나, 병합 전에는 Actions 화면에서 이 브랜치를 골라 수동 실행한다.
4. 첫 실행 뒤 Actions 기록과 `data/output/last_update.json`에서 다음 두 가지를 확인한다. FnGuide 컨센서스 표 해석과 네이버 시세 해석은 이 환경에서 실제 페이지로 시험하지 못했다.

## 4. 저장 규칙(재수집 방지)

- `facts`: 분석에 쓰는 대표값이다. 값이 바뀌면 **새 버전**을 만들고, 이전 값은 `is_current=0`으로 남긴다(변경 이력).
- `observations`: 출처와 보고서별 원본 관측값이다. 후속 보고서의 전기 열(재작성 값)도 따로 보관한다.
- `consensus`: 수집 기준일마다 새로 쌓는다. 같은 시점 자료가 다시 오면 무시하고, 덮어쓰지 않는다.
- `fetch_log`: 요청 기록이다. 확인했지만 자료가 없던 항목은 7일 동안 다시 묻지 않는다.
- 갱신 조건: 빈 값, 새 분기·사업보고서, 정정 공시(그 연도만 STALE로 바꾼 뒤 재수집), 컨센서스(7일), 기준일 주가(1일), 사용자 재검증 요청.
- 대표값 선택: 그 연도 자신의 보고서를 먼저 쓰고, 정정 공시가 있으면 최신 접수번호를 쓴다. 그 보고서가 없으면 그 연도를 처음 담은 후속 보고서의 값을 쓴다.

검증 상태

| 상태 | 뜻 |
|---|---|
| VERIFIED | DART 원천 계정: 자산=부채+자본이 맞고 다른 출처와 어긋나지 않음. 계산 지표: 입력값이 모두 VERIFIED |
| UNVERIFIED | 검증이 끝나지 않음(예: 공식 주식 수 없이 역산한 BPS·시가총액) |
| CONFLICT | 출처 간 불일치, 또는 회계 등식 불일치 |
| CORRECTED | 정정 공시로 값이 바뀜 |
| STALE | 정정 공시 확인 또는 재검증 요청으로 다시 받아야 함 |
| MISSING | 자료 미확보 |

## 5. 지표 계산식

| 지표 | 계산 |
|---|---|
| 매출액(억원) | 연결 매출액 ÷ 1억 |
| 영업이익률(%) | 영업이익 ÷ 매출액 × 100 |
| EPS(원) | 연결 손익계산서의 기본주당이익(보통주) 원본 |
| BPS(원) | 지배주주 자본 ÷ (보통주+우선주−자기주식). 공식 주식 수가 없으면 역산 주식수(지배순이익÷EPS)를 쓰고 UNVERIFIED로 표시 |
| ROE(%) | 지배주주 순이익 ÷ (전년말+당년말 지배주주 자본)/2 × 100 |
| 부채비율(%) | 부채총계 ÷ 자본총계 × 100 |
| 시가총액(억원) | 연말 보통주 종가 × 보통주 발행주식수(우선주 제외). 공식 주식 수가 없으면 역산 주식수 사용(주의 표시) |

- 현재 연도: 부채비율·BPS·시가총액은 최신 실제값(반기말, 기준일)을 쓴다. 매출·EPS·ROE는 컨센서스를 쓰고, 부분 실적(H1 등)은 연간 값처럼 그리지 않고 표와 툴팁에만 보여준다.
- 통합 그래프 표준화: 모든 값이 양수이고 기준값이 최댓값의 5% 이상이면 `첫해=100` 지수로 그린다. 아니면 기간 최솟값을 0, 최댓값을 100으로 놓고 정규화한다. 지표별 방식은 화면 C에 표시한다.

## 5-1. 가치평가(화면 G)

| 탭 | 내용 |
|---|---|
| 주가 vs 주당가치 | 연말 주가(현재 연도는 기준일 주가) 위에 S-RIM, DCF(FCFF), PER·PBR·PSR 가치, 종합(중앙값)을 겹쳐 그림. 값 차이가 8배를 넘으면 처음부터 로그 축 |
| ROIC vs WACC | 두 선을 겹치고 사이를 색칠(ROIC>WACC 초록 = 가치 창출, 반대 빨강 = 가치 훼손). 자기자본비용 Ke를 점선으로 함께 표시 |
| 계산 근거 표 | 연도별 Rf, Ke, Kd, 세율, WACC, ROIC, NOPAT, 투하자본, FCFF, 차입금, 현금, 실제·적정 배수 |
| 가정 | 계산식과 가정값(`analyzer/assumptions.json`) |

계산식(모두 지배주주 기준)

| 항목 | 계산 |
|---|---|
| Ke | 그해 국고채 10년 연평균 + 베타(1.0) × 시장위험프리미엄(5.5%) |
| Kd | 이자지급 ÷ 평균 차입금. 1% 미만·15% 초과면 Rf + 1.5%p |
| 세율 | 법인세 ÷ 세전이익. 0~50% 밖이거나 세전이익 ≤ 0이면 25% |
| WACC | 시가총액 비중 × Ke + 차입금 비중 × Kd × (1−세율) |
| ROIC | 영업이익 × (1−세율) ÷ 평균(자본총계 + 차입금·사채·리스부채 − 현금·단기금융상품) |
| S-RIM | B + B×(ROE−Ke)×0.9 ÷ (1+Ke−0.9). ROE는 최근 3년 3:2:1 가중 |
| DCF(FCFF) | FCFF = 영업현금흐름 − 유형·무형자산 취득 + 영업활동 이자지급×(1−세율). 3년 3:2:1 가중 → ×(1+g)/(WACC−g) − 순차입금 → 지배지분 비율 |
| PER·PBR·PSR 가치 | 그 연도까지 자기 배수의 중앙값(최소 3년) × EPS·BPS·주당매출. 적자 해는 PER 제외 |
| 종합 | 계산된 방법이 3개 이상일 때만 중앙값 |
| 현재 연도 | 재무상태는 최근 분기·반기말, 흐름은 최근 12개월(전년 연간 + 올해 누적 − 전년 같은 기간), 주가는 기준일 |
| 미래 연도 | 컨센서스(EPS·BPS·ROE·매출)가 있을 때만. DCF 제외 |

빈칸 규칙: 가중 FCFF ≤ 0, DCF 지분가치 ≤ 0, 차입금 줄이 재무상태표 본문에 따로 없을 때(예: 메디톡스 2017~2022, 금융부채에 포함), 적정 배수 관측이 3년 미만인 경우에는 값을 내지 않고 이유를 '계산 메모'에 적습니다. WACC − g < 3%p이면 DCF가 크게 부풀 수 있다는 주의를 붙입니다.

## 6. 다른 종목에 적용하기

1. `DART_API_KEY`를 설정한다(로컬 실행 시 `export DART_API_KEY=키`).
2. `python -m analyzer analyze 종목코드`를 실행한다. DART 고유번호 목록은 처음 한 번만 받아서 `data/corp_codes.json`에 저장한다.
3. 키가 없는 환경이라면 `analyzer/seed/<종목코드>/`에 DART 응답 JSON(`dart_<연도>_<보고서코드>_CFS.json`), 시세 JSON(`prices_*.json`), 컨센서스 CSV(`consensus_*.csv`)를 넣으면 같은 방식으로 가져온다.
4. 컨센서스를 직접 넣을 때 쓰는 CSV 열은 아래와 같다. `as_of`(자료 기준일)는 반드시 적는다.
   `target_year,metric,value,unit,broker,n_estimates,provider,as_of,source_ref`

## 7. 알려진 한계(2026-11-04 기준)

- 공식 주식 수가 아직 없어서 BPS와 시가총액은 **역산 주식수로 계산한 UNVERIFIED 값**이다. 역산값은 연중 가중평균이라 증자·주식배당이 있었던 해에는 연말 값과 다르다(예: 한솔제지 2016년 역산 1,799만 주, 2018년 이후 약 2,378만 주). DART 키를 넣고 자동 수집을 한 번 돌리면 공식 주식 수로 바뀌고, 그 차이는 변경 이력에 남는다.
- 컨센서스(2026~2028년 전망)는 **미확보**다. FnGuide 수집기는 GitHub Actions에서 처음 시험된다.
- 한솔제지는 우선주가 있다. 시가총액은 보통주만 계산한다.
- 2026년 3분기보고서는 기준일 현재 수집하지 않았다(법정 제출기한은 11월 중순).
- 메디톡스의 2026년 분기 실적은 아직 넣지 않았다(자동 수집 때 채워짐).
